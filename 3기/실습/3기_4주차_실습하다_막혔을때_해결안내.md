실습하다 막히셨다면 **내 상황과 맞는 항목 하나만** 보세요. 처음부터 다시 하실 필요는 없습니다.

## 1. 무엇을 물어봐야 할지 모르겠어요

**실습 안내서 주소와 지금 막힌 내용을 함께 보여 주세요.** 오류의 뜻을 몰라도 됩니다.

### 지금 하실 것

1. [학습자료](https://study.saedongne.com/automation/board.html?board=9)에서 하던 실습의 안내서를 엽니다.
2. 안내서가 열린 인터넷 창 맨 위 **주소창**을 한 번 누르고 `Ctrl+C`로 주소를 복사합니다.
3. **ChatGPT 앱(Codex)의 그 실습 대화**에 주소를 붙여넣고, 아래 상자도 함께 보냅니다.

```text
이 안내서의 실습을 하려고 해. 나는 컴퓨터를 잘 몰라.
지금 막힌 내용은 이 글 아래에 붙일게.
안내서와 내가 이미 한 작업을 먼저 확인해 줘.
네가 확인·설치·수정·실행할 수 있는 것은 직접 해결해 줘.
기존 파일은 지우지 말고, 내가 꼭 해야 하는 것만 쉬운 말로 한 단계씩 알려 줘.
끝에는 실제로 무엇이 만들어졌는지, 어디에서 확인하는지 알려 줘.
실제로 성공한 것을 확인하기 전에는 해결됐다고 말하지 마.
```

그 아래에 **Codex가 한 말이나 오류 문구**를 붙여넣습니다. "준비 4에서 막혔어요"처럼 안내서의 단계도 적으면 좋습니다.

**오류 화면만 있나요?** Windows에서 `Windows 키+Shift+S`를 누르고 필요한 부분을 드래그해 찍습니다. 질문 입력창을 누르고 `Ctrl+V`로 붙여넣습니다. 비밀번호·인증번호·봇 토큰이 보이는 부분은 빼고 찍어 주세요.

**성공 확인:** AI의 "끝났습니다"라는 말과 함께, 실제 결과 파일·웹 화면·휴대폰 메시지가 보이는지 확인합니다.

<a id="chat"></a>
## 2. 같은 말만 반복해요 / Codex에게 말을 걸 수 없어요

**같은 방법으로 두 번 실패했다면 [ChatGPT.com](https://chatgpt.com)에 물어보세요.** Codex가 아예 켜지지 않아도 이 방법으로 다음 행동을 안내받을 수 있습니다.

### 지금 하실 것

1. 크롬이나 엣지에서 [chatgpt.com](https://chatgpt.com)을 열고 본인 계정으로 로그인합니다.
2. 실습 안내서 주소와 아래 상자를 붙여넣습니다.
3. 그 아래에 **막힌 단계, 오류 문구, 이미 해 본 것**을 붙여넣습니다.

```text
이 안내서의 실습을 하다가 막혔어. 나는 컴퓨터 초보자야.
아래에 막힌 단계와 ChatGPT 앱(Codex)이 한 말, 이미 해 본 것을 붙일게.
같은 실패를 반복시키지 말고 다음에 할 행동을 하나씩 쉽게 알려 줘.
Codex가 대화 가능한 상태라면, 거기에 그대로 복사해서 붙여넣을 해결 문장을 만들어 줘.
내가 직접 해야만 하는 일은 어느 앱에서 무엇을 누르는지 순서대로 설명해 줘.
내 화면을 확인하지 않고 메뉴 위치나 원인을 단정하지 마.
파일 삭제·재설치·Windows 보안 끄기부터 권하지 마.
```

**참고:** ChatGPT.com은 해결 방법을 알려 주는 곳입니다. 거기서 "고쳤다"고 말해도 내 컴퓨터의 파일이 실제로 바뀐 것은 아닐 수 있습니다. Codex에 해결 문장을 전달하거나, 안내받은 조작을 한 뒤 결과를 확인해 주세요.

<a id="app"></a>
## 3. 보내기 화살표가 회색이에요 / 앱이 흰 화면이에요

### 컴퓨터 유즈가 없거나 앱을 못 볼 때

ChatGPT 데스크톱 앱의 **Plugins → Computer Use**에서 설치·활성화를 확인합니다. Mac의 **화면 기록·손쉬운 사용 권한**과 앱별 접근 허용은 따로 확인합니다. Windows는 대상 앱이 활성 데스크톱에 보여야 합니다. 전체 액세스 설정만으로 모든 앱의 로그인과 접근 권한이 생기지는 않습니다. 설정 위치가 다르면 현재 화면과 [공식 안내](https://learn.chatgpt.com/docs/computer-use)로 확인하세요.

### 보내기 버튼만 안 눌릴 때

1. 왼쪽에서 **지금 실습하는 프로젝트**를 선택했는지 확인합니다. 처음이면 안내서에서 정한 실습 폴더를 연결합니다. [폴더 안내](#folder)를 보세요.
2. 입력한 글 맨 끝을 한 번 누르고 **스페이스바를 한 번** 누른 다음 보내기를 눌러 봅니다. 한글 입력이 끝나지 않은 상태인지 확인하는 간단한 방법입니다.
3. 앞 작업이 아직 진행 중인지 확인합니다. 멈춤·중지 버튼이 보이면 현재 작업 상태를 먼저 봅니다.
4. 여전히 안 되면 입력한 글을 복사해 메모장에 보관하고 앱을 완전히 종료했다가 다시 엽니다.

**성공 확인:** 내가 보낸 글이 대화에 올라가고 Codex가 답을 시작합니다. 버튼이 안 눌리는 원인은 이 점검만으로 확정할 수 없습니다.

### 흰 화면·모델 오류 때문에 대화 자체가 안 될 때

1. 쓰던 글을 보관하고 ChatGPT 앱을 완전히 종료했다가 다시 엽니다. 창만 닫은 뒤 오른쪽 아래 작업 표시줄에 ChatGPT 아이콘이 남아 있으면 그 아이콘의 오른쪽 버튼 메뉴에서 종료합니다.
2. 계속 안 되면 [2번](#chat)의 방법으로 ChatGPT.com에 **그 화면과 오류 문구**를 보여 주세요.
3. `model is not supported`라는 문구가 보이면 **그 영어 문구 전체**를 붙여넣고, 내 앱에서 고를 수 있는 모델과 업데이트 여부를 확인하는 방법을 요청합니다. 안내서에 적힌 예전 모델 이름을 억지로 입력하지 않습니다.

앱이 안 돼도 **자동화하고 싶은 일을 정리하는 문서**는 ChatGPT.com에서 먼저 만들 수 있습니다. 내 컴퓨터의 파일을 만들고 프로그램을 실행하는 실습은 앱이 실행된 뒤 이어갑니다.

### 명령을 실행해도 되냐는 허락 창이 뜰 때

이것은 오류가 아니라 **내 허락을 기다리는 화면**일 수 있습니다. 명령의 뜻을 모르겠으면 같은 대화에서 "이 명령이 무엇을 하는지, 파일을 바꾸거나 밖으로 보내는지 쉬운 말로 설명해 줘"라고 물어보세요. 하려던 작업에 필요한 명령인지 확인하고 「한 번만 허용」을 누릅니다.

<a id="folder"></a>
## 4. 폴더를 고르라고 해요 / 어제 하던 일을 이어가고 싶어요

**그 실습에 쓰던 프로젝트와 대화를 먼저 엽니다.** 같은 이름의 폴더를 계속 새로 만들지 않습니다.

### 폴더를 못 찾겠다면 Codex에 보내세요

```text
이전에 이 실습에서 만든 폴더를 찾아 줘. 같은 폴더를 새로 만들지는 마.
지금 작업하는 폴더의 전체 위치와, 그 안에 이미 있는 실습 파일을 확인해 줘.
작업 폴더를 내가 직접 골라야 한다면 선택할 폴더와 화면에서 누를 것을 쉽게 알려 줘.
파일을 지우거나 옮기지는 마.
```

녹음 비서 실습의 2장까지 했다면 `녹음자동처리` 폴더 안에 `inbox`, `notes`, `tools`, `models`, `logs` 다섯 폴더가 있는지 확인하게 합니다. **이 단계에서는 `config`가 없어도 됩니다.** `config`는 뒤의 텔레그램 설정 단계(보통 13장, 12-2장 대체 방법을 쓰면 그때)에서 만듭니다. 컴퓨터마다 「문서」의 위치가 다를 수 있습니다.

**내가 직접 폴더를 골라야 할 때:** 프로젝트의 폴더 선택 창에서 Codex가 알려 준 위치를 엽니다. 선택할 폴더 이름을 한 번 누르고 「폴더 선택」을 누릅니다. 해당 버튼이 보이지 않으면 화면을 찍어 [2번](#chat) 방법으로 물어보세요.

### 다음 날 이어갈 때

```text
이 실습을 이어서 하자. 안내서와 이 폴더에 있는 파일을 읽어 줘.
어디까지 실제로 완료됐고 어디부터 남았는지 확인해 줘.
이미 된 것은 다시 만들지 말고, 남은 첫 단계부터 진행해 줘.
내가 직접 할 일만 한 단계씩 알려 줘.
```

**참고:** 컴퓨터에서 돌아가는 녹음 처리·알림은 컴퓨터를 끄면 멈춥니다. 켠 뒤 자동으로 다시 시작하도록 준비됐는지는 Codex에게 실제 설정을 확인하게 하세요.

<a id="aside"></a>
## 5. Aside 브라우저·CLI·스킬 중 어디에서 막혔나요?

**Aside 창이 켜진 것만으로 준비가 끝난 것은 아닙니다.** 아래 네 가지를 따로 확인합니다. 모르는 영어 명령은 직접 입력할 필요 없이 아래 문장을 ChatGPT 앱(Codex)에 복사해 보내세요.

| 확인할 것 | 준비가 된 모습 |
|---|---|
| 브라우저 | Aside가 열리고 내 Aside 계정으로 로그인돼 있습니다. |
| CLI: AI가 Aside를 부르는 연결 도구 | Codex에서 설치 위치·버전을 확인하고, 계정 확인 명령도 성공합니다. |
| 스킬: AI가 읽는 Aside 사용 안내 | Codex가 `aside-browser`를 인식하고 실제 `SKILL.md`를 읽습니다. |
| 실제 웹 작업 | 실습할 Codex 대화에서 Aside로 실제 페이지를 읽고 제목·주소·읽은 내용을 알려 줍니다. |

**ChatGPT 계정과 Aside 계정의 이메일은 달라도 됩니다.** 네이버·티스토리 같은 사이트 로그인도 따로 합니다. 오류의 **“같은 사용자(same OS user)”는 이메일이 아니라 Windows에서 명령을 실행하는 사용자**를 뜻합니다. 두 앱을 같은 사람이 열었어도 Codex의 보호된 실행 공간에서는 다른 Windows 계정으로 명령이 실행될 수 있습니다.

<a id="aside-cli"></a>
### A. 「aside 명령을 찾지 못했다」고 해요

1. [사전준비 안내서의 CLI 복구](https://github.com/aiautomationstudy/study_exercises/blob/main/3기/실습/3기_3주차_사전준비_안내서.md#aside-명령을-못-찾을-때) 상자를 **ChatGPT 앱(Codex)**에 보냅니다. 이미 설치한 앱·파일은 보존합니다.
2. Aside 창의 **Settings → Developers**에서도 CLI 설치·업데이트를 할 수 있습니다. 화면에 보이는 단추 이름은 버전에 따라 다르므로, 못 찾겠으면 그 화면을 보여 주세요.
3. 설치 직후 명령을 못 찾으면 **ChatGPT 앱을 완전히 종료했다 다시 열어** 새 실행 경로를 인식하게 합니다. 먼저 하던 작업을 저장하고 실행 중인 일이 끝났는지 확인합니다. Windows에서 창의 ×만 눌렀는데 앱이 남아 있다면, 화면 오른쪽 아래 숨겨진 아이콘에서 ChatGPT의 종료 메뉴가 있는지 확인합니다. Mac은 ChatGPT 앱에서 **⌘+Q**입니다.

명령을 찾았어도 계정 확인이 실패했다면 아래 C로 갑니다. 앱을 다시 설치하는 단계로 돌아가지 않습니다.

<a id="aside-skill"></a>
### B. 「aside-browser 스킬이 없다」고 해요

**`aside skills list`에 Gmail·Notion 등이 나오는 것은 Aside 안의 서비스용 스킬 목록입니다. Codex의 `aside-browser` 설치 확인과 다릅니다.** 기존 스킬을 지우거나 사용자 폴더를 바꾸기 전에 아래 문장을 보냅니다.

```text
Aside CLI는 있지만 Codex에서 aside-browser 스킬을 찾지 못했어.
현재 Codex가 실제로 읽는 사용자·프로젝트 스킬 위치부터 확인해줘.
aside skills install --help를 읽고, 지원하면 공식 명령 aside skills install --target codex로 설치해줘.
실제 설치한 SKILL.md 경로와 name·description을 확인하고 내용을 읽어줘.
현재 공식 사용자 경로는 내 사용자 홈의 .agents/skills야. 다른 위치에 설치됐다면 이 Codex가 인식하는지 실제로 확인해줘.
이미 있는 파일은 보존하고, 출처 모를 설치 스크립트나 스킬을 만들지 마.
접근 거부나 명령 미지원이면 원문을 알려주고 멈춰. 관리자 권한이나 보안 해제부터 요구하지 마.
프로젝트 안에만 설치했다면, 다른 프로젝트에서도 쓰는 공통 설치와 구분해줘.
파일을 만들었다는 말만 하지 말고, 앱을 다시 열어 새 대화에서 인식·읽기를 확인하는 방법을 알려줘.
```

**Codex가 쓰기 권한 때문에 설치하지 못할 때만:** 기존 스킬 파일이 없다는 것을 확인했고, 현재 CLI가 위 공식 설치 명령을 지원한다면 **직접 연 일반 Windows PowerShell**에서 아래 한 줄을 실행할 수 있습니다. PowerShell 여는 법은 아래 C에 있습니다. 기존 파일이 있다면 먼저 보존하도록 안내받고, 무조건 덮어쓰지 않습니다.

```powershell
aside skills install --target codex
```

설치 위치가 표시되면 Codex에 알려 주고 새 대화에서 읽는지 확인합니다. 명령 미지원·접근 거부가 나오면 그 오류를 보존하고 멈춥니다.

기존 작업이 끝난 뒤 앱을 다시 열고 **같은 실습 폴더의 새 Codex 대화**에서 “aside-browser 스킬을 읽고 어디에서 읽었는지 알려줘”라고 합니다. 파일이 있어도 인식되지 않으면 준비 완료로 넘기지 않습니다. 전역 작업 규칙을 적은 파일과 스킬 파일도 서로 다릅니다.

### C. 켜져 있는데 인증·권한 오류가 나요

| 보이는 말·상황 | 다음에 할 일 |
|---|---|
| `Cannot open Windows installation key` / `local authentication failed` | 공식 안내는 Windows 실행 계정 차이를 우선 확인합니다. 키를 지우거나 로그아웃·재설치하지 않습니다. |
| `EPERM` + `mkdir`·`rename`·`native` 경로 | 실패한 파일 경로와 실행 환경을 확인합니다. 같은 폴더 권한 허용 뒤에도 실패했다면 그 결과를 재사용합니다. |
| `EACCES 127.0.0.1:21420` / `fetch failed` / `Aside isn't running` | Codex가 내 PC의 Aside 서비스에 접근하는지 확인합니다. 인터넷 전체가 안 된다거나 앱이 꺼졌다고 단정하지 않습니다. |
| `uv_os_get_passwd returned ENOMEM` | 이 문구만으로 RAM 부족이나 한글 사용자 이름이 원인이라고 단정하지 않습니다. 실제 실행 계정과 실패 명령을 기록합니다. |
| `sandbox_approval` 차단·승인 창이 안 뜸 | 명령이 실행되지 않은 것과 실행 후 실패한 것을 구분합니다. 이미 차단된 승인 요청을 반복하지 않습니다. |
| 일반 PowerShell에서는 성공, Codex에서만 실패 | 설치·Aside 로그인 성공과 Codex 연결 실패를 나눠 기록합니다. 아래 비교 문장을 보냅니다. |
| Remote Control·Pro 결제를 요구함 | 원격 기능을 로컬 인증 오류의 필수 해결책으로 삼지 않습니다. Remote debugging과 Remote Control도 다른 설정입니다. |
| 계정이 로그아웃 상태임 | Aside의 Settings → Account에서 본인 계정을 확인합니다. CLI가 별도 기기 승인을 요구할 때만 안내에 따라 승인하고, CLI의 로그인 성공까지 확인합니다. |

**같은 명령을 두 환경에서 비교하는 문장 — ChatGPT 앱(Codex)에 보내세요.**

```text

계정 목록 성공만으로 웹 제어도 성공했다고 하지 마.
필요한 명령 하나만 추가 허용하는 방법이 이 환경에서 지원되면, 명령·범위·이유를 설명하고 승인받아 확인해줘.
```

**내가 직접 PowerShell 확인을 해야 할 때만:** Windows 키를 누르고 `PowerShell`을 입력한 뒤 **Windows PowerShell**을 엽니다. **관리자 권한으로 실행**은 누르지 않습니다. 아래 한 줄만 그 창에 붙여넣고 Enter를 누릅니다. 이 한 줄은 **PowerShell용**이고, 다른 설명 상자는 **ChatGPT 앱(Codex)용**입니다.

```powershell

```

이미 같은 확인을 했다면 반복하지 않습니다. 평소 실행도 관리자 창으로 열리거나 위 명령을 못 찾으면, 설정을 바꾸지 말고 그 사실만 알려 주세요. 계정 이메일은 가리고 **성공했는지와 오류 문구**만 전달해도 됩니다. 직접 연 창에서 성공해도 Codex에서의 웹 작업이 복구됐다는 뜻은 아닙니다.

### E. 연결이 계속 막히면 실습은 어떻게 하나요?

- **Aside 자체 AI 대화가 이미 정상 동작할 때만** 그곳에서 조사 문장을 보내고, 출처 주소·확인 날짜가 있는 결과를 원래 Codex 대화에 전달합니다. 새 결제·모델 연결 화면이 나오면 멈춥니다.
- 자체 AI도 쓸 수 없다면 **내가 Aside 주소창에서 공식 페이지를 직접 열어** 확인한 주소와 내용을 Codex에 전달하고, 안내문 만들기·수정하기를 먼저 연습할 수 있습니다. Codex가 직접 웹을 읽었다고 기록하지 않습니다.
- 두 방법 모두 **Codex 연결 복구와는 별개**입니다. 이미 만든 파일과 진단 결과를 보존하고, [11번 질문 양식](#question)으로 남깁니다. 운영진이 내 PC의 승인 정책을 원격으로 바꿨다고 생각하고 기다릴 필요는 없습니다.

공식 확인: [Aside CLI·설치](https://docs.aside.com/help/developers), [Windows 인증키 오류](https://docs.aside.com/help/troubleshooting#cli-cannot-open-the-windows-installation-key), [Codex 스킬 위치](https://learn.chatgpt.com/docs/build-skills), [Windows 실행 권한](https://learn.chatgpt.com/docs/windows/windows-sandbox). **CLI만 인증 실패하는 경우와 Aside 앱 자체가 반복 종료되는 경우는 다릅니다.** 공식 문서의 다른 증상용 키 복구 절차를 이 오류에 그대로 적용하지 마세요.

| `ffmpeg`를 찾지 못한다고 함 | "ffmpeg가 실제로 있는지 확인하고 없으면 설치해 줘. 내가 명령어를 입력하지 않도록 직접 실행까지 확인해 줘." |
| 일부 결과만 생김 | "이미 생긴 결과를 지우지 말고, 어느 단계에서 멈췄는지 확인해서 빠진 문서만 만들어 줘." |
| 한글 사용자명·폴더 이름이 원인이라고 함 | "실제 오류와 경로로 확인해 줘. 내 Windows 사용자 이름은 바꾸지 마. 경로 문제로 확인되면 원본을 보존하고 실습 파일만 안전한 위치에서 시험해 줘." |
| 5분마다 검은 창이 떠서 불편함 | "기존 자동 처리가 검은 창을 띄우는지 확인해 줘. 처리는 유지하고 조용히 실행할 수 있게 수정·검증해 줘." |
| Windows가 프로그램을 막음 | "탐지 화면과 프로그램 출처를 확인해 줘. Windows 보안을 끄거나 폴더 전체를 예외로 하지 말고 다음에 할 한 가지만 알려 줘." |

**심화실습 #3을 먼저 시작하셨나요?** #3은 #2의 **Part 5 「브라우저 관제판 만들기」까지** 준비가 필요합니다. Codex에 "#3을 시작하려고 해. #2의 Part 5까지 내 폴더에 무엇이 준비됐는지 확인하고 빠진 것부터 진행해 줘"라고 보내세요.

## 8. 휴대폰 녹음 옮기기·Notion 연결에서 막혔어요

이 부분은 녹음 비서의 **선택 확장**입니다. 여기서 막혀도 컴퓨터에 직접 넣은 녹음 한 개를 정리하는 기본 실습부터 끝낼 수 있습니다.

| 막힌 곳 | 지금 하실 것 |
|---|---|
| 휴대폰에서 컴퓨터로 녹음이 안 넘어옴 | 먼저 녹음 하나를 컴퓨터의 `inbox`에 직접 옮겨 기본 처리를 확인합니다. 휴대폰 전송 설정은 아래 문장으로 따로 맡깁니다. |
| Notion에 페이지가 안 생김·권한 오류 | 연결하려는 Notion 페이지를 열고 아래 문장과 오류를 Codex에 보냅니다. 비밀번호·연결용 비밀값은 보내지 않습니다. |

```text
녹음 비서의 휴대폰 전송 또는 Notion 연결에서 막혔어.
어느 단계인지는 아래에 적을게. 이미 컴퓨터에서 되는 녹음 처리는 그대로 보존해 줘.
내가 쓰는 휴대폰과 전송 앱, 또는 연결하려는 Notion 페이지의 권한을 실제로 확인해 줘.
네가 수정할 수 있는 설정·프로그램은 직접 해결해 줘.
휴대폰에서 권한을 누르거나 Notion 페이지에서 연결을 허용해야 한다면,
어느 기기의 어떤 앱에서 무슨 버튼을 누르는지 한 단계씩 알려 줘.
연결 비밀번호나 비밀값을 대화창에 달라고 하지 마.
끝에는 녹음 한 개가 실제로 넘어왔는지 또는 Notion 페이지가 실제로 생겼는지 확인해 줘.
```

## 9. 자료·과제는 어디에 있나요? 결과는 어떻게 올리나요?

### 자료 다시 보기

[스터디 허브](https://study.saedongne.com/automation/)에서 **학습자료**를 누릅니다. 주차별 안내서와 녹화 영상을 찾아볼 수 있습니다. 아직 시작하지 못했다면 하려던 기본 실습 안내서 하나부터 보세요. 이 안내서는 새 과제가 아니라 **막힌 곳을 해결하는 도움말**입니다.

### 결과 올리기

1. [과제·실습 공유](https://study.saedongne.com/automation/board.html?board=13)를 엽니다.
2. 「글쓰기」를 누르고 **제목**과 **무엇을 만들어 봤는지** 적습니다.
3. 공개해도 되는 결과 링크를 붙이거나 캡처 이미지를 올립니다. 캡처 붙여넣기가 안 되면 글쓰기 화면의 **이미지 첨부**에서 저장한 PNG/JPG 파일을 선택합니다.
4. 저장한 뒤 내 글을 다시 열어 **이미지나 링크가 실제로 보이는지** 확인합니다.

미완성이어도 어디까지 됐고 어디에서 막혔는지 함께 적을 수 있습니다. 질문은 [묻고 답하기](https://study.saedongne.com/automation/board.html?board=16)에 남겨 주세요.

**`.md` 파일만 있나요?** Codex에 "이 문서를 읽기 편한 HTML 파일로 만들어 줘. 내가 내용을 확인한 뒤 공유할 수 있게 해 줘. 아직 공개하지는 마"라고 요청합니다. `.md`는 글 문서입니다. MarkText로 열면 보기 편합니다. 메모장에서 보이는 `#`·`**`는 문서 서식 표시입니다.

요구사항 정의서에 대한 **개별 답변은 해당 학습자료 글의 댓글**에서 확인합니다. 파일 첨부·본문 길이 오류가 나면 같은 글을 여러 번 올리지 말고 오류 화면과 글 제목을 질문에 함께 적어 주세요.

## 10. 음성 입력·사용 한도·사이트 수정에서 막혔어요

### 말을 했는데 엉뚱한 글자가 나와요

지금 실습은 **글로 입력해서 먼저 이어갈 수 있습니다.** Windows의 「음성 녹음기/녹음기」에서 짧게 녹음해 내 목소리가 들리는지 확인합니다. 들리지 않거나 ChatGPT에서만 잘못 받아쓰면 그 결과와 화면을 [ChatGPT.com](https://chatgpt.com)에 보여 주고 한 단계씩 점검해 달라고 하세요. 마이크 고장이라고 단정하지 않습니다.

### 사용 한도에 도달했다고 나와요

화면에 나온 **도구 이름·한도 안내·다시 쓸 수 있는 시각**을 확인합니다. 어떤 서비스의 한도인지 모른 채 추가 결제하지 않습니다. ChatGPT.com을 쓸 수 있으면 화면을 보여 주고 "지금 한도가 무엇인지, 추가 결제 없이 언제 무엇을 할 수 있는지 설명해 줘"라고 물어보세요. 기다리는 동안에는 안내서를 읽거나 다음에 만들 내용을 메모해 둘 수 있습니다.

### 만든 사이트가 수정되지 않아요 / 게시가 차단됐어요

```text
이미 만든 사이트를 수정하려다 막혔어. 아래에 사이트 주소와 오류를 붙일게.
원본 파일과 현재 공개된 화면을 각각 확인해 줘.
어떤 수정이 저장됐고 실제 사이트에는 무엇이 반영됐는지 구분해 줘.
가능한 수정은 기존 결과를 보존하고 직접 진행해 줘.
게시 권한이나 로그인에서 사람이 할 일이 있다면 한 단계씩 알려 줘.
실제 사이트를 다시 열어 확인하기 전에는 반영됐다고 말하지 마.
이미 실패한 방법을 반복하거나 보호 설정을 임의로 바꾸지 마.
```

허락 요청조차 안 된다는 오류가 반복되면 [2번](#chat)으로 옮겨 물어보세요. 임시로 컴퓨터에서 열리는 결과 파일을 만들 수 있는지도 확인하게 합니다. **컴퓨터에서 보이는 파일과 다른 사람이 볼 수 있는 공개 사이트는 다릅니다.**

## 12. 폴더와 Git은 무엇이 다른가요?

**폴더는 실제 작업 파일이 있는 곳, Git은 그 폴더의 변경 기록을 남기는 도구, GitHub는 기록을 올려 보관하는 서비스**입니다. 같은 폴더에서 Git을 함께 쓰는 것이므로 둘 중 하나를 고르는 문제가 아닙니다.

큰 작업을 Git으로 관리하면 바뀐 부분을 비교하고, 언제 무엇을 바꿨는지 확인하며, 다른 PC에서도 이어갈 수 있습니다. 비공개 저장소로 혼자 사용해도 됩니다. **파일과 지침을 기록해야 새 Codex 대화가 읽고 이어갈 수 있습니다.** Git이 예전 대화를 전부 기억하거나 자동 백업·공개 발행하는 것은 아닙니다.

| 용어 | 쉽게 말하면 |
| --- | --- |
| 저장소·레포 | 프로젝트 파일과 변경 기록을 모아 둔 곳 |
| 클론 | 원격 저장소를 내 컴퓨터에 처음 가져오기 |
| 상태 확인 | 내가 바꾼 파일과 현재 브랜치 확인하기 |
| 페치·풀 | 원격의 새 기록 받기. fetch는 받아 보고, pull은 받기와 통합을 함께 합니다. |
| 커밋 | 내 컴퓨터에서 변경 묶음에 설명을 붙여 기록하기 |
| 푸시 | 내 커밋을 GitHub 같은 원격에 올리기 |
| 배포·발행 | 실제 사이트나 블로그에서 다른 사람이 이용하게 반영하기. 푸시와 별도이며 자동 연결돼 있을 수도 있습니다. |

```text
지금 작업 폴더에서 Git을 쓰는지 먼저 확인해줘.
이미 연결된 저장소·원격·브랜치·미커밋 변경을 확인하고 재사용해줘.
내 파일을 덮어쓰거나 같은 폴더를 또 클론하지 마.
깨끗한 작업본일 때 원격을 fetch하고, 현재 프로젝트의 기준 브랜치로 ff-only 최신화를 해줘.
미커밋 변경·분기·충돌이 있으면 보존하고 어떤 선택이 필요한지 알려줘.
저장소가 없다면 내 계정의 비공개 저장소로 준비하는 방법을 보여줘.
비밀번호·토큰·개인정보·팀 내부 자료는 Git에서 제외해줘.
README에 사용법, AGENTS.md에 작업 규칙, PROGRESS.md에 완료·남은 일을 기록해줘.
공개 저장소를 비공개로 바꾸는 것만으로 이미 공개된 자료가 회수되지는 않는다는 점도 확인해줘.
실제 원격 반영을 확인하고 푸시와 배포 상태를 구분해서 알려줘.
```

본인 비공개 저장소도 서비스 약관·회사 규정과 자료 소유권을 따라 사용합니다. 나중에 공개하기 전에 파일뿐 아니라 커밋 이력도 확인하세요.
