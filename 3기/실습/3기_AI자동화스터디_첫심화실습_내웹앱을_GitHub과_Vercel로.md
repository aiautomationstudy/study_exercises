> 걸리는 시간은 **1시간~1시간 30분**(추정)입니다. 한 번에 다 못 하셔도 됩니다.  
> 중간에 멈춰도 다음 날 이어서 하면 됩니다.

> **📌 다 했으면 게시판에 공유해 주세요**
>
> 1. 게시판의 **‘실습 공유’** 탭을 엽니다.

> 4. 본문에 **Vercel 주소**(`……vercel.app`)를 붙여 넣습니다.
>
> 끝까지 못 갔어도 괜찮습니다. **“STEP 5까지 했습니다”** 처럼 어디까지 했는지만 올려도 됩니다.

# 1. 이 실습으로 얻는 것

기본 실습에서 만든 웹앱은 지금 **ChatGPT 안에** 있습니다.  
이 실습이 끝나면 그 웹앱이 **세 군데에 더** 있게 됩니다.

```
ChatGPT 안 (Sites)
   ↓ 내려받기
① 내 컴퓨터의 폴더          ← 파일로 내 손에 있습니다
   ↓ 올리기
② GitHub (코드 보관함)        ← 잃어버리지 않습니다
   ↓ 연결
③ Vercel (인터넷 주소)        ← 내 컴퓨터를 꺼도 켜져 있습니다
```

그리고 **앞으로 고칠 때**는 이렇게 됩니다.

> 내 컴퓨터의 ChatGPT 앱(Codex)에게 말로 고치라고 한다  
> → Codex가 고쳐서 GitHub에 올린다  
> → Vercel이 알아서 새 버전으로 바꿔 준다

이게 개발자들이 실제로 일하는 방식입니다. 오늘 그걸 한 번 겪어 보는 겁니다.

### 처음 보는 이름 세 개

| 이름 | 이렇게 생각하시면 됩니다 |
|---|---|
| **Codex** | ChatGPT 앱 안에 있는, **내 컴퓨터의 파일을 직접 다루는** AI. 브라우저의 ChatGPT는 대화만 하지만 Codex는 폴더를 열고 파일을 만들고 프로그램을 설치합니다 |
| **GitHub** | 전 세계 개발자가 쓰는 **코드 보관함**. 무료입니다 |
| **Vercel** | GitHub에 올린 웹앱을 **인터넷 주소로 켜 주는 곳**. 개인 용도는 무료입니다 |

- [ ] 시간 1시간 남짓

- 신용카드 — GitHub도 Vercel도 무료로 씁니다.

| STEP | 하는 일 | 누가 하나 |
|:--:|---|---|

# STEP 1. 내 웹앱 코드를 zip으로 내려받기

■ 꼭 하셔야 하는 것

1. 브라우저에서 **chatgpt.com** 에 들어갑니다.
2. 기본 실습에서 웹앱을 만들었던 **그 대화창**을 다시 엽니다.  
   (못 찾겠으면 왼쪽 메뉴 **「더보기」→「Sites」** 또는 주소창에 `chatgpt.com/sites` — 내 사이트 목록이 나옵니다)
3. 대화창에 이렇게 말합니다.

> “지금 만든 이 사이트의 **전체 소스 코드를 zip 파일 하나로** 묶어서 내려받을 수 있게 해 줘.  
> zip 파일 이름은 영문 소문자로 지어 줘.”

4. ChatGPT가 주는 **내려받기 링크**를 누릅니다.
5. zip 파일이 **다운로드 폴더**에 들어옵니다.  
   (어디 갔는지 모르겠으면 브라우저에서 `Ctrl + J` — 받은 파일 목록이 뜹니다)

<!-- 스태프 확인: Sites 화면에 코드 내려받기 버튼이 있는지, Work 대화에서 zip 요청이 되는지 09-16 전에 실제로 해 보고 캡처 넣기. 공식 문서에는 내려받기 방법이 적혀 있지 않음 -->

■ 잘 안될 때

- 사이트 화면에 **「내려받기(Download)」·「내보내기(Export)」** 같은 버튼이 보이면 그걸 눌러도 됩니다.
- zip이 안 만들어지면 → STEP 2에서 **빈 폴더**를 만들고 STEP 3에서 그 폴더를 연 뒤, Codex에게 이렇게 말하세요.

> “내 ChatGPT Sites에 있는 **‘○○○’** 사이트의 코드를 이 폴더로 가져와 줘.  
> 가져올 수 없으면 이 주소(사이트 주소 붙여넣기)의 사이트를 직접 열어 보고, **같은 기능·같은 디자인**으로 여기에 다시 만들어 줘.”

# STEP 2. 내 컴퓨터에 작업 폴더 만들기

앞으로 이 스터디에서 만드는 것은 **전부 한 폴더 아래**에 둡니다.  
폴더 이름은 **`ai-work`** 입니다. 위치는 **내 홈 폴더 바로 아래**입니다.

| | 폴더 위치 |
|---|---|
| 윈도우 | `C:\Users\내이름\ai-work` |
| 맥 | `/Users/내이름/ai-work` |

> **왜 「문서」 폴더가 아닌가요?**  
> 윈도우의 「문서」 폴더는 OneDrive와 자동으로 동기화되는 컴퓨터가 많습니다.  
> 코드 폴더가 거기 있으면 동기화가 계속 돌면서 파일이 잠기는 문제가 생깁니다.  
> 홈 폴더 바로 아래는 동기화되지 않습니다.

■ 꼭 하셔야 하는 것

**① `ai-work` 폴더 만들기**

- **윈도우**: 파일 탐색기를 엽니다 → 위쪽 **주소창**을 클릭하고 `%USERPROFILE%` 이라고 친 뒤 Enter  
  → 내 홈 폴더가 열립니다 → 빈 곳에서 마우스 오른쪽 → **새로 만들기 → 폴더** → 이름을 `ai-work` 로
- **맥**: Finder를 엽니다 → 위쪽 메뉴 **「이동」→「홈」** → 메뉴 **「파일」→「새로운 폴더」** → 이름을 `ai-work` 로

**② zip 파일을 옮기고 풀기**

1. 다운로드 폴더의 zip 파일을 `ai-work` 폴더 안으로 **끌어다 놓습니다.**
2. zip 파일을 **마우스 오른쪽 → 「압축 풀기」** (맥은 더블클릭)
3. 풀린 폴더를 열어 봅니다. **파일들이 바로 보여야 합니다.**  
   폴더 안에 또 같은 이름의 폴더 하나만 있으면, 그 **안쪽 폴더를 `ai-work` 로 끌어내고** 바깥 폴더는 지웁니다.

**③ 폴더 이름을 내 웹앱에 맞게 바꾸기**

풀린 폴더 이름은 보통 알아보기 어렵습니다. 마우스 오른쪽 → **「이름 바꾸기」**

이름 규칙은 세 가지뿐입니다. **영문 소문자 · 숫자 · 하이픈(-)** 만 씁니다. 공백과 한글은 쓰지 않습니다.

| 내 웹앱 | 폴더 이름 예 |
|---|---|
| 점심 메뉴 추천기 | `lunch-menu-picker` |
| 등산 모임 홈페이지 | `hiking-club-site` |
| 출장 준비 체크리스트 | `trip-checklist` |
| 단체 주문 견적 계산기 | `group-order-calc` |

이름 짓기가 어려우면 ChatGPT에게 물어보세요.

> “‘점심 메뉴 추천기’에 어울리는 **영문 폴더 이름**을 소문자와 하이픈만 써서 3개 추천해 줘.”

다 되면 이런 모양입니다.

```
ai-work
└── lunch-menu-picker
    ├── index.html
    ├── (그 밖의 파일들…)
```

■ 잘 안될 때

- `%USERPROFILE%` 을 쳐도 안 열리면 → **C 드라이브 → 사용자(Users) → 내 이름** 폴더로 직접 들어가세요.
- 「압축 풀기」가 안 보이면 → zip 파일을 더블클릭해서 열고, 안의 내용을 전부 선택해 새 폴더로 끌어다 놓으세요.
- 폴더 이름에 한글이나 공백을 넣으면 뒤에서 GitHub·Vercel이 막힙니다. 지금 바꿔 두세요.

# STEP 3. ChatGPT 앱의 Codex로 폴더 열기

여기서부터 **컴퓨터에 설치한 ChatGPT 앱**을 씁니다. 브라우저가 아닙니다.

■ 꼭 하셔야 하는 것

1. **ChatGPT 앱**을 엽니다.
2. 왼쪽에서 **「Codex」** 를 고릅니다.
3. **「새 프로젝트 추가(Add new project)」** 를 누릅니다. (단축키: 윈도우 `Ctrl + O`, 맥 `Cmd + O`)
4. 폴더 고르는 창이 뜨면 `ai-work` → **내 웹앱 폴더**(예: `lunch-menu-picker`)를 고르고 **「폴더 선택」**
5. 입력창 아래에 **「승인 요청(Ask for approval)」** 이 선택돼 있는지 봅니다. 그대로 둡니다.

<!-- 스태프 확인: 한국어 화면의 실제 버튼 이름과 위치 캡처. 문서상 명칭은 "Add new project", Ctrl+O -->

> **승인 창이 뜨면 이렇게 하세요**  
> Codex는 프로그램을 설치하거나 명령을 실행하기 전에 **“이거 해도 돼?”** 하고 물어봅니다.  
> 내용을 읽고 **「승인(Approve)」** 을 누르면 됩니다. 이 실습에서는 여러 번 뜹니다. 정상입니다.  
> **“파일을 삭제”** 하겠다는 내용이면 누르지 말고 Codex에게 “왜 지워야 해?” 하고 물어보세요.

6. 입력창에 아래 **프롬프트 ①** 을 그대로 붙여 넣고 보냅니다.

### 프롬프트 ① — 폴더 점검하고 배포 준비하기

```
이 폴더는 ChatGPT의 Sites에서 만든 웹앱을 내려받아 압축을 푼 것이야.
나는 컴퓨터 초보자야. 설명은 초보자에게 하듯 쉽게 해 줘.
아래를 순서대로 해 줘.

1. 이 폴더 안에 무엇이 들어 있는지 짧게 설명해 줘.
2. 이 웹앱을 GitHub에 올리고 Vercel에 배포할 수 있게 정리해 줘.
   - Vercel에서 그대로 동작하는 형태로 만들어 줘. 정적 HTML/CSS/JS로 되면 가장 좋아.
   - Cloudflare나 ChatGPT Sites 전용 설정 파일이 있으면 빼거나 Vercel용으로 바꿔 줘.
   - 서버에 데이터를 저장하는 기능이 있으면, 브라우저 안에 저장하는 방식(localStorage)으로 바꿔 줘.
3. 이름·전화번호·주소·계좌번호 같은 개인정보가 들어 있는 파일이나 내용이 있으면
   작업을 멈추고 어디에 있는지 알려줘.
4. README.md 파일을 한국어로 만들어 줘. 이 웹앱이 무엇인지, 어떻게 쓰는지 짧게.
5. .gitignore 파일을 만들어 줘.
6. 다 되면, 내 컴퓨터에서 이 웹앱을 어떻게 미리 볼 수 있는지 한 줄로 알려줘.
```

7. Codex가 끝나면 알려주는 대로 **미리 보기**를 열어 봅니다. 기본 실습 때와 같은 화면이 나오면 됩니다.

■ 잘 안될 때

- Codex가 **“개인정보가 있습니다”** 라고 하면 → 진짜 개인정보면 **그 파일을 지우거나 가짜 값으로** 바꿉니다. 연습용 가짜 자료면 “연습용 가짜 자료야, 계속해 줘”라고 말합니다.
- 미리 보기 화면이 기본 실습 때와 다르면 → “기본 실습 때는 ○○가 있었는데 지금은 없어. 원래대로 살려 줘.”
- 무슨 말인지 모르겠으면 → “지금 한 일을 컴퓨터 모르는 사람에게 설명하듯 다시 말해 줘.”

# STEP 4. GitHub 계정 만들기

이미 계정이 있으면 로그인만 하고 STEP 5로 가세요.

■ 꼭 하셔야 하는 것

1. 브라우저에서 **https://github.com** → 오른쪽 위 **「Sign up」**
2. **이메일** → **비밀번호** → **사용자 이름(Username)** 을 정합니다.  
   사용자 이름은 **영문 소문자와 숫자**로. 다른 사람에게 보이는 이름이라 실명이 아니어도 됩니다. (예: `sunny-kim-2026`)
3. 이메일로 온 **인증 코드**를 입력합니다.
4. 설문이 나오면 **「Skip」** 을 누릅니다. 요금제는 **Free** 그대로.
5. 로그인된 상태로 둡니다.

■ 잘 안될 때

- 인증 메일이 안 오면 → 스팸함을 보고, 없으면 **「Resend」**
- 사용자 이름이 이미 있다고 하면 → 뒤에 숫자를 붙이세요.

# STEP 5. 도구 설치하고 GitHub에 로그인하기

Codex가 GitHub에 올리려면 **작은 프로그램 두 개**(Git, GitHub CLI)가 컴퓨터에 있어야 합니다.  
설치는 Codex가 합니다. **로그인만 직접** 하시면 됩니다.

■ 꼭 하셔야 하는 것

**① 설치는 Codex에게 — 프롬프트 ②**

```
GitHub에 올리려면 git 과 GitHub CLI(gh)가 필요해.
내 컴퓨터에 설치되어 있는지 확인하고, 없으면 설치해 줘.
- 윈도우면 이 명령으로 설치해 줘:
  winget install --id Git.Git -e --accept-source-agreements --accept-package-agreements
  winget install --id GitHub.cli -e --accept-source-agreements --accept-package-agreements
- 맥이면 관리자 비밀번호 없이 되는 방법으로 설치해 줘.
설치가 끝나면 "설치 끝. 이제 gh 로그인이 필요합니다"라고 알려줘.
로그인은 내가 직접 할게.
```

승인 창이 뜨면 **「승인」**. 맥에서 **“명령어 라인 개발자 도구를 설치하겠습니까?”** 창이 뜨면 **「설치」** (10분쯤 걸립니다).

**② ChatGPT 앱을 완전히 껐다가 다시 켭니다.**

새로 설치한 프로그램을 앱이 알아보게 하려면 꼭 필요합니다.  
윈도우: 화면 오른쪽 아래 작은 아이콘들 중 ChatGPT 아이콘 → 마우스 오른쪽 → **「종료(Quit)」** → 다시 실행  
맥: `Cmd + Q` → 다시 실행

**③ GitHub 로그인 — 이건 직접 하십니다 (한 번만)**

터미널이라는 검은 창을 씁니다. 처음이면 낯설지만 **Enter 몇 번과 복사 한 번**이 전부입니다.

1. 터미널을 **새로** 엽니다.  
   윈도우: 시작 버튼 → `터미널` 이라고 검색 → 열기  
   맥: `Cmd + Space` → `터미널` 입력 → Enter
2. 이 한 줄을 붙여 넣고 Enter:

```
gh auth login
```

3. 질문이 **네 개** 나옵니다. **전부 그냥 Enter** 를 누릅니다. (처음 보이는 답이 다 맞는 답입니다)

```
? Where do you use GitHub?                          → Enter
? What is your preferred protocol for Git operations? → Enter
? Authenticate Git with your GitHub credentials?      → Enter
? How would you like to authenticate GitHub CLI?      → Enter
```

4. 그다음 **8자리 코드**가 나옵니다. 이런 모양입니다: `! First copy your one-time code: AB12-CD34`  
   이 코드를 **적어 두거나 복사**합니다.
5. Enter 를 한 번 더 누르면 브라우저가 열립니다. (안 열리면 https://github.com/login/device 로 직접)
6. 브라우저에 **코드를 입력** → **「Continue」** → **「Authorize github」**
7. 터미널로 돌아오면 **`✓ Logged in as 내이름`** 이 보입니다. 끝입니다. 터미널을 닫아도 됩니다.

■ 잘 안될 때

- **`gh` 를 찾을 수 없다**고 하면 → 터미널을 **닫고 새로** 여세요. 설치 전에 열어 둔 창은 새 프로그램을 모릅니다.
- **winget 이 없다**고 하면 → Codex에게 “winget 없이 설치해 줘. git-scm.com 과 cli.github.com 의 설치 파일을 써 줘.”
- 터미널 여는 게 어려우면 → Codex에게 “**터미널 창을 새로 열고 그 안에서 `gh auth login` 을 실행해 줘.** 질문 답은 내가 할게.”
- 브라우저에서 GitHub 비밀번호를 다시 물으면 → 입력하시면 됩니다. 정상입니다.

# STEP 6. GitHub에 올리기

■ 꼭 하셔야 하는 것

ChatGPT 앱의 Codex(STEP 3에서 연 프로젝트)에 **프롬프트 ③** 을 붙여 넣습니다.

### 프롬프트 ③ — GitHub에 올리기

```
gh 로그인을 마쳤어. 이 폴더를 GitHub 저장소로 올려 줘.
- 저장소 이름은 이 폴더 이름과 똑같이.
- 비공개(private)로 만들어 줘.
- git 사용자 이름과 이메일이 설정되어 있지 않으면 내 GitHub 계정 정보로 설정해 줘.
- 첫 커밋 메시지는 "첫 배포 준비"로.
- 다 되면 저장소 주소(https://github.com/…)를 알려줘.
```

승인 창이 뜨면 **「승인」**.

**확인**: 브라우저에서 https://github.com 에 들어가 오른쪽 위 내 아이콘 → **「Your repositories」**.  
내 폴더 이름과 같은 저장소가 보이면 성공입니다.

■ 잘 안될 때

- **“로그인이 안 되어 있다”** 고 하면 → STEP 5-②(앱 완전히 껐다 켜기)를 했는지 확인하고 다시.
- **“저장소 이름이 이미 있다”** 고 하면 → “이름 뒤에 `-3gi` 를 붙여서 만들어 줘.”
- 그 밖의 오류 → Codex가 보여 준 오류 내용을 그대로 두고 “이 오류를 초보자에게 설명하듯 알려주고 고쳐 줘.”

# STEP 7. Vercel에 가입하고 배포하기

이 단계는 **전부 브라우저에서 버튼을 누르는 일**입니다.

■ 꼭 하셔야 하는 것

**① 가입 (GitHub 계정으로 — 새 비밀번호가 필요 없습니다)**

1. https://vercel.com → 오른쪽 위 **「Sign Up」**
2. 요금제를 물으면 **「Hobby」**, 이름을 넣습니다.
3. **「Continue with GitHub」** → GitHub 화면에서 **「Authorize Vercel」**
4. Vercel 대시보드가 열립니다.

**② 배포**

1. **「Add New…」→「Project」**
2. **「Import Git Repository」** 에서 **처음이면 「Install」** 을 누릅니다  
   → GitHub 화면에서 **「Only select repositories」→ 내 저장소 선택 → 「Install」**
3. 목록에 내 저장소가 보이면 **「Import」**
4. 설정 화면은 **아무것도 건드리지 말고** 아래 **「Deploy」**
5. 1~2분 기다립니다. **「Congratulations!」** 가 나오면 성공입니다.
6. **「Continue to Dashboard」**

<!-- 스태프 확인: Vercel 가입 때 휴대폰 인증을 요구하는지 실제로 해 보기 -->

■ 잘 안될 때

- 배포가 **실패(Error)** 로 끝나면 → 빨간 글씨의 오류 내용을 드래그해 복사한 뒤 Codex에 **프롬프트 ④**:

```
Vercel 배포가 실패했어. 아래는 Vercel 화면에 나온 오류야.
원인을 초보자에게 설명하듯 알려주고, 고쳐서 GitHub에 다시 올려 줘.
Vercel이 자동으로 다시 배포할 거야.

(여기에 오류 내용 붙여넣기)
```

  Codex가 올리면 Vercel이 **알아서 다시 배포**합니다. 대시보드에서 기다리면 됩니다.
- 휴대폰 인증을 요구하면 → 진행하시면 됩니다. 요금은 나가지 않습니다.
- 내 저장소가 목록에 안 보이면 → 「Install」 화면에서 그 저장소를 **선택했는지** 다시 확인.

# STEP 8. 주소 확인하고 공유하기

■ 꼭 하셔야 하는 것

**① 내 주소 찾기**

대시보드에서 내 프로젝트를 누르면 **「Domains」** 에 주소가 있습니다.  
**짧은 주소**를 씁니다. 이런 모양입니다: `lunch-menu-picker.vercel.app`

**② 진짜로 열리는지 확인**

**휴대폰**(와이파이 말고 데이터로)에서 그 주소를 열어 봅니다. 내 웹앱이 뜨면 **누구나 열 수 있는 것**입니다.

**③ 게시판에 공유**

1. 게시판 **‘실습 공유’** 탭 → **‘글쓰기’**  
   👉 https://study.saedongne.com/automation/board.html?board=13
2. 제목 맨 앞에 **`[심화 실습]`**. 예: `[심화 실습] 점심 메뉴 추천기`
3. 본문에 **Vercel 주소**를 붙여 넣습니다. 한 줄 소감을 덧붙이면 더 좋습니다.

■ 잘 안될 때 — **로그인 화면이 뜬다면**

- 주소가 **길고 중간에 영문·숫자가 뒤섞여** 있으면(예: `lunch-menu-picker-git-main-abc123.vercel.app`) 그건 미리보기 주소입니다. 로그인을 요구합니다.  
  → 「Domains」의 **짧은 주소**를 쓰세요.
- 짧은 주소인데도 로그인 화면이 뜨면 → 프로젝트 **「Settings」→「Deployment Protection」→「Vercel Authentication」** 을 **끄고(Off)** → **「Save」**
