오늘은 내 말투와 기준에 맞는 블로그 글 한 편을 만들고, 고쳐서 저장합니다. 이미 블로그가 있으면 한 곳만 씁니다. 블로그가 없어도 원고부터 만들 수 있습니다.

오늘의 순서: 글감 알려 주기 → 원고 읽기 → 고쳐서 저장하기. 공개 발행은 원할 때 이어갑니다. 두 번째 블로그·GitHub 보관·검색 등록·광고·정기 발행은 첫 글 다음에 필요한 것부터 더합니다.

시작 전에: 이 안내서는 어디에서 보나요?

컴퓨터에서 이 안내서를 열어 두세요. 휴대폰으로 읽고 있다면 같은 주소를 컴퓨터에서도 엽니다. 실습은 컴퓨터에서 합니다.

화면 두 개를 번갈아 씁니다.

  • 이 안내서: 읽고 「문장 복사」를 누르는 곳입니다.
  • ChatGPT 앱(Codex): 복사한 문장을 보내고, AI의 답을 읽는 곳입니다. 인터넷 주소창이나 스터디 Q&A에 붙이지 않습니다.

매번 이렇게 합니다.

  1. 이 안내서에서 초록색 「문장 복사」를 누릅니다.
  2. ChatGPT 앱(Codex)으로 갑니다. 화면 아래 메시지를 쓰는 빈칸을 한 번 누릅니다.
  3. 키보드의 Ctrl을 누른 채 V를 누릅니다. Mac은 ⌘를 누른 채 V입니다.
  4. 글이 들어갔는지 보고 보내기 화살표를 누릅니다.
  5. AI의 답을 읽고 필요한 질문에 답합니다. 한 단계가 끝난 뒤 다음 문장을 보냅니다.

문장이 길어도 직접 입력하거나 외울 필요는 없습니다. 복사 단추가 없는 Markdown 화면이라면 문장 상자 안의 글 전체를 선택해 복사하세요.

0. 앱과 내 작업 폴더 열기

전에 하던 실습이 있나요? ChatGPT 앱(Codex)의 왼쪽 목록에서 그때의 대화를 누르세요. 같은 일을 다시 시작하거나 파일을 지울 필요는 없습니다.

처음인가요?

  1. 컴퓨터에서 ChatGPT 앱을 열고 Codex를 선택합니다.
  2. 새 채팅(New chat)을 엽니다. 파일을 저장할 폴더를 고르라는 화면이 나오면, 아래 방법으로 내 실습 폴더를 만듭니다.
  3. 폴더 선택 화면에서 문서 → 새 폴더를 누르고 아래 안내된 이름을 적습니다. 만든 폴더를 선택합니다. 폴더는 이번 실습의 파일을 모아 두는 곳입니다.
  4. Aside도 켜 둡니다. AI가 인터넷을 열어 일하는 모습을 확인하는 프로그램입니다.

화면에 「프로젝트 추가(Add new project)」나 「폴더 열기」가 보이면 그것으로 내 실습 폴더를 열어도 됩니다. 모델 이름이나 추론 설정은 지금 바꾸지 않아도 됩니다.

앱이 없거나 로그인부터 안 되나요? 앱·Aside 준비 안내를 보세요. 이미 설치한 프로그램은 다시 설치하지 않습니다. 로그인은 본인 계정으로 하고, 비밀번호·인증번호는 AI 대화창에 쓰지 않습니다.

처음 만드는 폴더 이름은 blog-practice로 적으세요. 전에 블로그를 작업한 폴더와 대화가 있으면 그대로 이어갑니다. 다른 실습 폴더에 원고를 섞지 않습니다.

Aside 연결을 아직 확인하지 못했다면: 준비 문장 펼치기

다음 문장으로 준비를 확인한 뒤 1단계로 갑니다. 연결이 안 돼도 글 한 편을 쓰고 저장하는 단계는 진행할 수 있습니다. 실제 블로그 화면 조작은 연결을 확인한 뒤 합니다.

같은 실습 대화에 보내세요
나는 컴퓨터 초보야. 이 대화에서 실습을 이어가고 싶어.
이미 설치한 앱과 만든 파일은 보존하고, 내 실습 폴더부터 확인해줘.
ChatGPT 앱(Codex)에서 Aside로 직접 웹 작업을 할 준비가 됐는지 확인해줘.
설치된 aside-browser 스킬과 현재 공식 가이드를 읽고, 실제 연결 상태를 확인해줘.
웹 작업은 Codex인 네가 aside repl로 직접 해줘. Aside 안의 별도 AI에게 작업을 넘기지 마.
준비가 덜 됐다면 아래 준비 안내서에서 내 컴퓨터에 해당하는 부분만 확인해줘.
https://github.com/aiautomationstudy/study_exercises/blob/main/3기/실습/3기_3주차_사전준비_안내서.md
준비 안내서 읽기와 Aside 자체 설치·복구에 필요한 공개 자료는 공식 주소와 위 안내서에서 내려받아도 돼.
반복 설치하거나 보안 설정을 모두 끄지 말고, 같은 오류가 두 번 나면 멈추고 알려줘.
내가 로그인하거나 허락해야 할 때는 어느 화면에서 무엇을 누르는지 한 가지씩 알려줘.
끝나면 준비된 것, 아직 안 된 것, 내가 다음에 할 일을 쉬운 말로 알려줘.
아직 조사나 글 작성은 시작하지 마.

1. 내 블로그와 글감 알려 주기

아래 문장을 보냅니다. AI가 질문하면 내 답을 한두 문장씩 적어 보내세요. 모르는 것은 “모르겠어요”라고 답해도 됩니다.

같은 실습 대화에 보내세요
내 블로그 글 한 편을 함께 만들자. 나는 컴퓨터를 잘 몰라.
이미 만든 블로그 폴더·원고·작업 기록이 있으면 확인해서 이어 써줘.
처음이면 지금 선택한 blog-practice 폴더를 사용해줘. 다른 프로젝트에 파일을 섞지 마.
다음 세 가지를 한 번에 하나씩 물어보고, 내 대답을 기다려줘.
1. 사용할 블로그가 네이버인지 티스토리인지, 아니면 아직 없는지
2. 이번에 쓰고 싶은 주제와 내가 직접 겪었거나 확인한 사실
3. 내 글에 원하는 말투와 꼭 지킬 기준
한 곳만 선택하고, 사진이 없으면 글부터 진행해줘.
내 경험을 지어내거나 남의 글을 내 글처럼 옮기지 마.
지금은 질문과 정리까지만 해줘. 발행·광고 신청·결제·예약은 하지 마.

답하는 예: “네이버 블로그가 있어요. 지난 주말에 걸었던 동네 산책길을 쓰고 싶어요. 담백한 존댓말로, 다녀온 척 지어내지 않고 써 주세요.”

지침 파일이 없어도 “문단은 짧게, 과장하지 않기, 내가 준 사실만 쓰기”처럼 말하면 됩니다. 팀 지침이 있다면 본인이 볼 수 있는 자료만 제공합니다. 사진이나 과거 카톡 대화를 처음부터 전부 준비할 필요는 없습니다.

다음으로 넘어갈 때: 쓸 주제 하나와 내 작성 기준이 정해졌습니다.

2. 원고를 읽고 한 가지 고치기

1단계의 같은 대화에 보냅니다.

같은 실습 대화에 보내세요
지금까지 내가 알려준 사실과 작성 기준으로 블로그 글 한 편을 써줘.
먼저 제목 하나와 짧은 문단으로 된 600자 안팎의 초안을 이 대화에 보여줘.
내가 제공하지 않은 경험·날짜·가격·효과를 만들어내지 마.
새 정보가 필요하면 공식 자료를 확인하고, 확인 못 한 것은 미확인으로 남겨줘.
초안을 보여준 뒤 내가 읽고 수정 의견을 줄 때까지 기다려줘.
아직 블로그 편집기에 넣거나 공개 발행하지 마.

원고를 읽고 내가 고치고 싶은 점 한 가지를 답합니다.

  • “글이 길어요. 절반으로 줄여 주세요.”
  • “첫 문장을 더 담백하게 바꿔 주세요.”
  • “그곳에는 가지 않았어요. 방문 후기처럼 쓴 부분을 고쳐 주세요.”

다음으로 넘어갈 때: 내 수정 의견이 반영됐고, 내가 말하지 않은 경험이나 잘못된 사실이 없습니다.

3. 고친 원고를 내 컴퓨터에 저장하기

같은 대화에 보냅니다.

같은 실습 대화에 보내세요
지금 고친 최종 원고를 내 블로그 실습 폴더에 첫-블로그-글.txt로 저장해줘.
같은 이름의 파일이 있으면 먼저 확인하고, 이전 원고는 사본으로 보존해줘.
내 글쓰기 기준과 오늘 한 일, 다음에 할 일도 같은 폴더에 기록해줘.
저장한 원고 파일을 내가 열어 읽을 수 있게 안내해줘.
폴더 위치와 파일 이름을 알려주고, 내가 원고가 저장된 것을 확인할 때까지 기다려줘.
블로그 공개 발행·새 계정 만들기·광고 신청·자동 발행 예약은 하지 마.

내 눈으로 확인할 것: 저장한 첫-블로그-글.txt를 열었을 때 방금 고친 원고가 보입니다. 파일을 여는 방법을 모르겠으면 “그 파일을 여는 순서를 한 가지씩 알려줘”라고 답하세요.

여기까지 되면 오늘의 기본실습을 마쳤습니다. 블로그가 없거나 아직 로그인하지 못했어도 원고를 고쳐 저장했다면 여기까지 진행한 것입니다. 다음에는 남은 단계부터 이어가세요.

선택: 원할 때 블로그에 올리기

저장은 내 컴퓨터에 파일을 두는 것이고, 발행은 블로그 독자에게 공개하는 것입니다. 공개해도 되는 원고인지 읽어 본 뒤, 아래 문장을 보냅니다.

같은 실습 대화에 보내세요
방금 확인한 최종 원고를 내가 선택한 블로그 한 곳에 올리고 싶어.
먼저 대상 블로그 주소와 실제 로그인 계정이 맞는지 나와 확인해줘.
내 글쓰기 기준을 적용하고, 사진은 내가 사용해도 되는 것만 써줘.
웹 조작은 Codex인 네가 Aside의 aside repl로 직접 해줘. 내 다른 탭은 건드리지 마.
로그인·본인 인증이 필요하면 내가 직접 할 화면만 안내하고 기다려줘.
우선 편집기에 넣고 미리보기를 보여줘. 최종 발행은 내가 확인하고 허락한 뒤에 해줘.
발행 뒤 실제 공개 글 주소를 열어 본문·사진·링크를 확인하고 내 작업 폴더에 기록해줘.
이미 발행됐는지 불명확하면 먼저 조회하고 중복 발행하지 마.
직접 조작이 안 되면 억지로 반복하지 말고, 내가 붙여넣는 순서를 한 가지씩 안내해줘.

공개를 원하지 않으면 이 단계는 건너뜁니다. AI가 직접 올리지 못해도, 내가 편집기에 붙여넣고 발행한 뒤 실제 글 주소를 알려 주어 확인할 수 있습니다. 비밀번호·인증번호는 대화창에 쓰지 않습니다.

새 대화에서 시작한다면 전에 원고를 저장한 블로그 폴더를 먼저 열어 주세요. 새 대화가 예전 작업을 전부 기억한다고 가정하지 말고, 기록을 읽게 합니다.

Notion 자료에 접근 권한이 없대요그 자료를 볼 수 있는 본인 계정인지 확인합니다. 다른 사람 자료라면 소유자에게 열람 권한을 요청합니다. 오늘 첫 실습은 Notion 없이 진행할 수 있습니다.
Windows 한글 사용자 이름·폴더에서 오류가 나요“실제 오류와 파일 위치를 확인하고 기존 자료는 보존해줘. 필요하면 사용 가능한 영문 이름의 실습 폴더에서 이어가줘”라고 보냅니다. Windows 계정 이름은 바꾸지 않습니다.

비밀번호·인증번호·쿠키는 프롬프트나 저장소에 적지 않습니다. 로그인, 본인 인증, CAPTCHA, 새로운 접근 권한과 약관 동의가 필요한 단계는 화면의 안내에 따라 본인이 확인하고 이어갑니다.

ChatGPT/Codex 로그인과 GitHub의 Git 푸시 인증은 별개입니다. GitHub 웹에 로그인했더라도 로컬 Git의 인증이 안 되어 있으면 푸시가 막힐 수 있습니다. 연결이 안 되면 AI에게 현재 인증·권한 상태와 필요한 로그인 화면을 확인하게 하세요. 도구 설치·유료 이용이 필요한 경우에는 현재 지원 여부와 비용을 먼저 확인합니다. 제공되지 않는 기능을 설치됐다고 가정해서 진행하지 않습니다.

Aside나 앱 제어를 사용할 수 없더라도 로컬 원고 작성·기록·커밋을 진행할 수 있습니다. 발행 단계는 본인이 편집기에 최종 원고와 사진을 넣는 방법으로 이어가고, 실제 공개 URL을 다시 전달해 검증·보관을 마무리합니다. 직접 로그인·동의가 필요한 단계는 그 화면만 처리한 뒤 같은 프로젝트에서 계속하세요.

준비가 끝나면 만든 블로그 폴더를 Codex 프로젝트로 열고 그 안에서 계속합니다. 저장소 생성이나 클론이 막히면 GitHub 로그인·권한을 확인합니다. 로컬 폴더만 만들어진 상태를 GitHub 보관 완료로 판단하지 않습니다.

예상 구조는 다음과 같습니다. 글 폴더 이름과 세부 파일명은 자신의 프로젝트에 맞춰도 됩니다.

커밋·푸시·발행·배포는 무엇이 다른가요?

작업 하는 일 블로그 공개 글이 바뀌나요?
저장 내 컴퓨터에 원고와 기록 파일을 남김 아니요
커밋 관련 변경을 묶어 Git에 수정 이유와 이력을 남김 아니요
푸시 커밋한 이력을 내 GitHub 저장소에도 보관 아니요
발행·수정 네이버·티스토리 편집기에 최종 원고를 반영하고 공개 해당 플랫폼에 반영됩니다
배포 직접 만든 사이트·프로그램의 변경을 실행 환경에 반영 별도 시스템을 연결한 경우에만 관련됩니다

이 실습의 Git 저장소는 작업하면서 쌓이는 자료와 판단을 보관하는 공간입니다. 블로그 글을 발행하지 않은 날에도 조사·기획·초안·수정 내용을 커밋할 수 있습니다. 별도 사이트나 프로그램을 만들지 않았다면 ‘배포’할 것은 없습니다. GitHub에 푸시했다고 블로그 발행까지 완료됐다고 판단하지 않습니다.

4. 내 지침과 참고 글 읽히기

카카오톡의 과거 대화를 전부 수집할 필요는 없습니다. 본인이 지정한 방에서 이번 작업에 필요한 지침과 참고 링크를 중심으로 읽게 합니다.

내용을 확인하고 필요한 문장을 복사하세요
앞서 알려준 내 지침 위치와 공개 참고 글을 읽고 이번 글을 준비해줘.
소속 블로그팀이 있으면 내가 참여 중인 방의 지침을 적용하고,
소속 방이 없으면 내가 준 개인 작성 기준을 적용해줘.

지침의 공유일·버전·바뀐 조건을 먼저 대조해줘.
MD 파일은 파일 내용을 실제로 열어 읽고, 첨부된 다른 자료도 필요한 범위를 확인해줘.
내부 자료는 내가 열람할 수 있는 것만 쓰고 공용 자료나 GitHub에 복제하지 마.

내 최근 글과 주제가 맞는 공개 이웃·팀원 글을 참고해줘.
제목만 본 글과 본문까지 읽은 글을 구분하고,
공개 링크와 배울 수 있는 구성만 짧게 기록해줘.
남의 문장·사진·경험을 내 것으로 가져오지 마.

Aside 작업 전 설치된 aside-browser 스킬과 서비스 전용 스킬을 확인해줘.
가능하면 전용 커넥터나 API를 쓰고,
브라우저가 필요하면 Aside 배경 탭에서 작업해줘.
Aside로 안 되는 부분은 이유를 설명하고 사용할 수 있는 다른 경로로 이어가줘.

이번 소재에 맞는 네이버 글과 티스토리 글의 역할,
사진 배치, 아직 필요한 사실을 준비 카드에 정리해줘.
이미 제공한 사실은 다시 묻지 말고 핵심적으로 부족한 것만 확인해줘.
우선 기획과 준비까지만 해줘.

완료 확인: 적용할 지침의 출처·공유일을 파악했고, 두 글이 각각 독자에게 무엇을 줄지 설명돼 있으면 다음 단계로 갑니다. 읽지 못한 자료가 있다면 내용을 추정하지 않고 다른 확인 가능한 자료로 보완합니다.

5. 네이버·티스토리 글을 서로 다르게 작성하기

두 플랫폼에 같은 글을 그대로 복사하는 대신, 같은 소재로 각각의 읽을거리를 만듭니다. 아래는 실습을 위한 일반적인 구성 예시이며, 각자의 지침에 따라 조정하세요.

네이버 글 티스토리 글
독자가 공감할 상황과 핵심 답 그 답을 더 자세히 실행하는 방법
사진과 짧은 문단으로 읽기 쉽게 HTML로 순서·비교·도움말을 정리
필요한 설명을 글 안에서 완결 독자의 후속 질문을 충분히 해결
추가 설명이 필요한 곳에 상세 글 링크 링크를 타고 온 사람이 얻을 추가 가치

예를 들어 네이버는 ‘내게 맞는 걷기 코스를 고를 때 보게 되는 것’을, 티스토리는 ‘거리·교통·휴식 장소를 비교하는 방법’을 다룰 수 있습니다. 이 예시도 실제 방문 경험으로 바꾸어 쓰지 않습니다.

내용을 확인하고 필요한 문장을 복사하세요
준비 카드와 내 지침에 맞춰 네이버·티스토리 원고를 각각 작성해줘.
두 글은 같은 소재를 공유하되 제목·도입·전개를 각각 설계해줘.
네이버 글 자체에서 독자의 기본 질문에 답하고,
티스토리는 그보다 더 구체적인 정보와 방법을 제공해줘.

네이버는 짧은 문단과 소제목, 자연스러운 사진 설명으로 구성해줘.
티스토리는 주제에 맞는 사진·여백·색상을 사용한 HTML로 만들고,
스타일이 블로그 전체에 영향을 주지 않게 글 영역 안으로 한정해줘.
휴대전화에서도 글과 사진이 잘 보이게 해줘.

사용할 권한이 있는 사진을 골라 assets에 보관해줘.
삽화가 필요하면 역할을 먼저 정해서 만들고, 사실을 입증하는 사진처럼 설명하지 마.
정보가 부족한 부분은 만들어 채우지 말고 확인하거나 글의 범위를 조정해줘.

티스토리 원고, 네이버 편집용 원고, 사진 배치와 미리보기를 저장해줘.
네이버에서 티스토리로 연결할 문구와 위치도 정해줘.
두 글의 사실·표현·중복·지침 적합성·사진·모바일 가독성을 검토해줘.
내가 검토할 수 있도록 원고와 미리보기를 열어줘. 아직 발행하지 마.

내 검토에서 볼 다섯 가지

  1. 내가 실제로 한 일과 자료로 확인한 정보를 정확히 구분했는가?
  2. 제목에서 약속한 답을 본문이 충분히 제공하는가?
  3. 두 글을 모두 읽었을 때 각각 얻는 것이 있는가?
  4. 사진이 제대로 배치됐고 사용할 권한이 있는가?
  5. 내 지침의 필수 조건을 충족했는가?

수정이 필요하면 ‘도입을 더 구체적으로’, ‘두 번째 사진을 방법 설명 옆에’, ‘이 문장은 내가 한 경험이 아니니 바꿔줘’처럼 해당 부분을 지정하세요.

6. 검토한 글을 발행하고 연결하기

첫 실습에서는 아래처럼 발행할 글과 공개 범위를 명확하게 요청합니다. 티스토리를 먼저 발행하면 네이버에 실제 상세 주소를 넣을 수 있습니다.

내용을 확인하고 필요한 문장을 복사하세요
검토한 이번 티스토리 글과 네이버 글을 내 블로그에 공개 발행해줘.
제목·본문·사진은 검토한 최종 원고를 사용해줘.
카테고리와 태그는 내 지침과 글의 내용에 맞게 적용해줘.

티스토리를 먼저 발행해서 실제 공개 주소를 확보한 뒤,
네이버 본문의 연결 문구에 그 상세 주소를 넣고 발행해줘.
사진은 두 플랫폼 편집기에 직접 업로드해줘.
티스토리 HTML에는 업로드된 네이티브 이미지 토큰을 사용해줘.

저장·발행 후에는 공개 화면을 열어 제목과 본문 누락,
이미지 실제 로딩, 연결 링크, 공개 상태를 확인해줘.
HTML 코드·마크다운 표시·이미지 토큰이 글에 그대로 보이지 않는지도 확인해줘.
문제가 있으면 고치고 다시 공개 화면으로 검증해줘.

게시물 주소·발행일·검증 시점·결과를 publication.json에 기록해줘.
최종 원고와 PROGRESS.md를 갱신하고 커밋·푸시해줘.
카카오톡에는 아직 보내지 마.

완료 확인: 실제 공개 URL 두 개가 있고, 사진이 표시되며, 네이버의 링크가 이번 티스토리 글로 이동해야 합니다. 편집기에 입력한 상태나 ‘발행’ 버튼을 눌렀다는 보고만으로 완료 처리하지 않습니다.

카카오톡 공유는 선택입니다. 공유가 필요하면 이번 두 글의 링크를 [방 이름]에 [메시지 내용]으로 조용히 보내줘처럼 대상과 내용을 지정하세요. AI는 전송 옵션의 조용히 보내기 항목과 전송된 메시지를 확인하고, 작업 기록에는 보낸 시점과 공개 링크만 남깁니다. 해당 기능을 사용할 수 없다면 일반 전송으로 바꾸기 전에 알려달라고 요청하세요.

7. 티스토리 Search Console 연결과 색인 요청

최초 한 번: 사이트 연결 확인

티스토리는 사이트맵을 자동 생성하며 일반적인 주소는 https://내블로그.tistory.com/sitemap.xml입니다. Google Search Console 플러그인도 제공합니다. 실제 관리 화면에서 제공 여부와 연결 상태를 확인하고, 개인 도메인을 사용하면 그 도메인의 속성·사이트맵 주소를 기준으로 합니다. 티스토리 사이트맵 안내, 서치콘솔 플러그인 안내.

내용을 확인하고 필요한 문장을 복사하세요
내 티스토리의 Google Search Console 연결을 확인하고 준비해줘.
기존에 연결돼 있으면 중복 등록하지 마.
현재 티스토리 관리 화면과 Search Console에서
내 Google 계정, 실제 블로그 주소, 속성의 소유권 확인 상태를 대조해줘.

제공되는 공식 연결 방식으로 진행할 수 있게 준비해주고,
Google 권한 동의나 인증이 필요하면 내가 확인할 화면을 보여줘.
소유권이 확인된 뒤 실제 사이트맵 주소와 제출 상태를 확인해줘.
이미 제출돼 있으면 상태만 확인해줘.
결과와 확인 시점을 프로젝트에 기록해줘.

새 글 발행 후: URL 검사와 요청

내용을 확인하고 필요한 문장을 복사하세요
방금 발행한 내 티스토리 글의 실제 URL을 Search Console에서 검사해줘.
필요하면 실제 URL 테스트를 하고, 색인 가능한 상태인지 확인해줘.
아직 색인되지 않았고 제출이 필요한 새 글이면 색인 생성을 요청해줘.
이미 요청을 접수한 같은 URL에는 변경 사유 없이 반복 요청하지 마.

현재 검사 상태, 요청 접수 여부, 확인 시간을 publication.json에 기록해줘.
요청 접수와 색인 완료를 구분해서 알려줘.
권한 부족이나 요청 제한이 있으면 그 상태를 기록하고 다음 조치를 알려줘.

사이트맵 제출과 플러그인 연결은 Google의 발견·수집을 돕습니다. 연결됐다는 사실이나 ‘색인 생성 요청됨’은 색인 완료·검색 노출 보장이 아닙니다. 요청에는 제한이 있으며 이후 URL 검사로 상태를 확인합니다. Google URL 검사 안내.

일반 블로그 글을 무조건 색인시키는 만능 API로 구성하지 않습니다. Google의 Indexing API는 JobPosting 또는 VideoObject에 포함된 BroadcastEvent 페이지용입니다. 이 실습의 일반 포스팅은 해당 API의 대상이 아닙니다. Google Indexing API 적용 범위.

네이버 블로그는 네이버의 검색 허용 설정과 공개 상태를 확인합니다. 티스토리 속성으로 네이버 글까지 색인 요청할 수는 없습니다. 네이버 주소의 Search Console 소유권을 확인할 수 있는지 별도로 판단하고, 할 수 없다면 불가 상태를 기록합니다.

8. 다음 글부터 줄어드는 작업

작업할 때마다 내 저장소에 쌓을 것

9. 글이 쌓이면 광고 신청 준비하기

블로그에서 광고로 수익을 받으려면 티스토리는 Google 애드센스, 네이버는 애드포스트를 살펴봅니다. Google Ads는 광고를 집행하는 서비스이므로 블로그에 광고를 달아 수익을 받는 애드센스와 구분합니다.

‘몇 편만 쓰면 무조건 승인’이라는 공통 기준으로 진행하지 않습니다. 꾸준히 글을 쌓으면서 독창적인 내용, 읽기 편한 구조, 사진·링크의 정상 동작과 현재 공식 가입·심사 조건을 확인합니다. 애드센스는 고유 콘텐츠와 사용자 경험을 안내하고, 네이버는 가입과 광고를 게재할 미디어의 등록·검수를 구분합니다. 애드센스 콘텐츠 준비, 애드포스트 가입 조건.
