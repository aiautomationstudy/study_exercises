02 · 자기 진단: 직함보다 최근의 증거

진단의 목적은 자신에게 직급을 붙이는 것이 아니라 다음에 연습할 책임을 찾는 것입니다. 최근 8~12주 작업을 펼쳐 놓고 30분 정도 적어 보세요. 이 기간은 기억을 돕기 위한 제안이며 회사의 평가 기간을 뜻하지 않습니다.

1. 작업 세 개를 고릅니다

성공한 작업 하나, 막혔던 작업 하나, 누군가와 함께한 작업 하나를 고릅니다. 아직 작업이 없다면 E3 첫 과제를 수행한 뒤 돌아옵니다.

각 작업에 다음을 적습니다.

작업 이름 / 기간:
누구의 어떤 문제였나:
누가 목표와 방법을 정했나:
내가 직접 판단한 부분 / AI·동료가 맡은 부분:
실제 결과 / 확인 방법 / 증거 위치:
출시 후 문제와 대응:
다시 한다면 바꿀 판단:

“AI로 앱 완성”보다 “모임 담당자가 엑셀을 다시 정리하던 일을 줄이려고 예약 목록을 만들었고, 실제 사용 중 발견한 중복 입력을 고쳤다”처럼 적습니다. 측정하지 않은 시간 절감은 적지 않습니다.

2. 일곱 축에서 관찰합니다

점수 합계는 내지 않습니다. 각 칸에 확인됨 / 시도 중 / 경험 없음 / 판단할 자료 없음 중 하나를 쓰고 증거를 붙입니다.

축 기본 증거 책임이 넓어질 때의 증거
문제 정의 기대 동작과 예외를 말할 수 있다 어떤 문제를 먼저 풀지 근거로 정했다
구현 이해 바뀐 파일·데이터 흐름을 설명한다 구조 선택의 장단점·전환 비용을 설명한다
검증 직접 실행하고 실패 사례를 확인했다 동료도 쓸 평가 기준·반복 검사를 만들었다
독립적 완수 막히면 필요한 정보를 모아 도움을 요청한다 계획·출시·운영·복구를 주도했다
협업과 성장 피드백을 반영하고 결과를 공유했다 다른 사람의 판단·실행이 나아졌다는 관찰이 있다
영향 범위 기능이나 프로젝트를 개선했다 팀·여러 팀·사업의 결과가 달라졌다
AI 활용과 책임 AI 산출물의 한계와 확인 범위를 설명한다 도구·모델 변경에도 품질·비용·권한을 관리한다

AI 대화 내용만으로는 충분하지 않습니다. 코드 변경, 실행 결과, 실제 사용 기록, 협업자의 관찰 중 적어도 하나와 연결합니다. AI가 써 준 칭찬이나 가상의 사용자 평가는 증거가 아닙니다.

3. 지금 가장 가까운 책임 범위를 찾습니다

아래 조건은 학습용 판별 질문입니다. 공식 자격 기준이 아닙니다.

읽을 문서 지금 관찰되는 상태 다음에 채울 증거
E3 작은 결과를 만들지만 설명·수정·검증에 도움이 필요하다 정해진 기능을 직접 확인하고 피드백으로 개선한 기록
E4 기능은 만들 수 있고 프로젝트 전체를 맡는 연습이 필요하다 요구사항부터 운영까지 독립적으로 완수한 기록
E5 프로젝트는 맡을 수 있고 팀의 다음 방향을 만드는 연습이 필요하다 우선순위 제안, 기술 판단, 동료와 이룬 팀 성과
E6 팀 안의 리더 역할을 하며 경계를 넘는 병목을 풀고 싶다 독립된 여러 주체가 채택한 해결책과 공동 결과
E7 여러 주체를 이끌며 더 큰 사업 기회를 검증하려 한다 중요한 기회 발굴, 전략 선택, 지속적인 사업·조직 성과

“E5를 읽는다”는 E5라고 판정했다는 뜻이 아닙니다. 현재의 강점과 다음 책임을 연습할 위치를 고르는 것입니다.

4. 과대평가하기 쉬운 경우를 걸러냅니다

  • 실행 화면이 예쁘다: 저장·권한·실패·재시작 후 동작까지 봤는가?
  • 서비스를 혼자 운영한다: 책임의 폭은 넓어도 규모·복잡성·이해관계 조율의 증거가 충분한가?
  • 에이전트를 여러 개 쓴다: 도구 수가 늘어난 것인가, 사람과 시스템의 성과가 늘어난 것인가?
  • 내가 없으면 멈춘다: 큰 기여의 증거일 수도 있지만 문서·권한·인계의 병목일 수도 있다. 둘을 구분했는가?
  • 매출이 생겼다: 고객 가치의 신호와 함께 운영·안전·재현성도 확인했는가?
  • 한 번 크게 성공했다: 운·시점·동료 기여와 내가 반복할 수 있는 판단을 구분했는가?

반대로 과소평가도 점검합니다. 위험한 기능을 빼서 사고 가능성을 줄인 판단, 다른 사람의 작업을 쉽게 만든 문서, 사용자 오해를 줄인 설명도 결과와 연결되면 기여입니다.

5. 다른 사람과 기준을 맞춥니다

코드를 볼 수 있는 동료·멘토 한 명, 결과를 쓰는 사람 한 명에게 다른 질문을 합니다.

대상 물어볼 질문
동료·멘토 “이 작업에서 내가 혼자 책임질 수 있다고 확인된 범위는 어디까지인가요?”
사용자·협업자 “이전과 비교해 어떤 일이 쉬워졌고, 여전히 불편한 것은 무엇인가요?”
의사결정자 “다음 수준의 역할을 맡기려면 어떤 결과를 더 보고 싶으신가요?”

좋은 피드백은 “잘한다”보다 상황·행동·영향·다음 기대가 구체적입니다. 서로의 판단이 다르면 평균을 내지 말고 어떤 증거를 다르게 해석했는지 확인합니다.

작성 예시: 프로젝트는 만들지만 운영은 불안한 경우

가상 사례: 지윤은 AI와 예약 웹앱을 만들어 소규모 모임에서 사용했습니다. 날짜 선택과 목록은 설명할 수 있지만, 다른 사용자의 예약을 읽지 못하게 하는 검사는 아직 없습니다. 배포 실패 때 되돌리는 방법도 확인하지 않았습니다.

“혼자 앱을 만들었으니 Senior”라고 결론 내리지 않습니다. 기능 구현은 확인됐고 프로젝트 운영은 아직 자료가 부족합니다. E4의 권한·복구 과제를 다음 2주 과제로 잡는 편이 현재 부족한 책임을 직접 연습하게 합니다.

오늘 남길 한 문장

나는 지금 __ 범위의 문제를 _ 증거로 책임질 수 있다. 다음 2주에는 책임을 연습하고, ___로 확인한다.

다음 행동은 실행 계획에서 정하고 진단 양식에 기록합니다. 진단표의 빈칸은 부족한 사람이라는 뜻이 아니라 아직 관찰하지 않은 경험입니다.
