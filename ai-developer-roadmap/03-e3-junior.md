# 03 · E3 Junior Engineer: 작은 문제를 믿고 맡길 수 있는 사람

**핵심 질문: “정해진 작은 기능을 만들고, 확인하고, 설명할 수 있는가?”**

이 단계는 모든 것을 혼자 아는 단계가 아닙니다. 모르는 점을 드러내고 필요한 도움을 받아, 맡은 작업을 작동하는 결과로 전달하는 단계입니다. AI를 많이 써도 좋습니다. 내가 무엇을 요청했고 무엇을 확인했는지는 남겨야 합니다.

## 기대하는 책임과 결과

| 책임 | 관찰할 수 있는 행동 | 남길 증거 |
|---|---|---|
| 요구 이해 | 시작 전에 정상 동작·예외·완료 조건을 적는다 | 짧은 작업 설명 |
| 작은 구현 | 기존 구조에 맞춰 한 기능씩 바꾼다 | 변경 파일과 이유 |
| 결과 확인 | 정상·빈 입력·잘못된 입력을 직접 시험한다 | 입력과 예상·실제 결과 |
| 이해와 설명 | 입력→처리→출력 흐름을 말한다 | 3분 설명 또는 메모 |
| 피드백 반영 | 지적을 재현하고 수정 결과를 보여 준다 | 수정 전후 기록 |

[Dropbox IC1 공개 설명](https://dropbox.github.io/dbx-career-framework/ic1_software_engineer.html)은 방향과 구체적인 지도를 받으며 정의된 작업을 수행하는 범위를 다룹니다. 여기서는 그 취지를 참고해 작은 기능의 완수와 이해에 초점을 맞춥니다. E3와 IC1이 같은 직급이라는 뜻은 아닙니다.

## 첫 프로젝트: 개인정보 없는 행사 준비 목록

한 화면에서 준비물을 추가하고, 완료로 표시하고, 지울 수 있게 만듭니다. 이름·연락처·결제 기능은 넣지 않습니다. 첫 목표는 많은 기능보다 작은 동작의 이해입니다.

**반드시 할 일**

1. 사용자 한 명과 “완료”의 의미를 정합니다. 자신이 실제로 쓸 상황이어도 됩니다.
2. 입력창·추가·완료·삭제의 네 동작을 글로 적습니다.
3. AI에게 파일 구조와 구현 순서를 먼저 설명하게 합니다.
4. 기능 하나를 만든 뒤 직접 실행합니다. 나머지도 같은 방식으로 진행합니다.
5. 빈 입력, 아주 긴 입력, 같은 항목 두 번, 새로고침을 시험합니다.
6. 데이터가 브라우저에만 저장된다면, 다른 기기와 공유되지 않고 브라우저 데이터 삭제 시 사라질 수 있다는 한계를 설명합니다.
7. 마지막으로 글자 크기나 정렬 방식 하나를 바꾸고 영향을 확인합니다.

처음부터 서버·로그인·데이터베이스를 모두 넣을 필요는 없습니다. 사용자의 필요가 생겼을 때 저장 방식과 권한을 확장합니다.

## AI와 작업하는 방법

```text
행사 준비 목록을 만들고 싶다.
입력, 추가, 완료 표시, 삭제만 필요하다.
먼저 화면·파일·데이터 흐름과 완료 조건을 설명해 줘.
내가 이해할 수 있게 작은 기능 하나씩 구현해 줘.
각 변경 뒤 내가 확인할 입력 예와 예상 결과를 알려 줘.
모르는 용어는 이 앱의 실제 동작으로 설명해 줘.
```

생성 뒤에는 “잘 됐지?” 대신 다음을 묻습니다.

- 저장되는 값은 어디에 있고, 언제 사라지는가?
- 이 버튼을 누르면 어느 코드가 실행되는가?
- 입력이 비어 있을 때 왜 이 동작을 하는가?
- 지금 직접 확인하지 않은 부분은 무엇인가?

AI 설명을 그대로 암기하지 말고 실행 결과와 맞춰 봅니다. 설명과 실제가 다르면 “방금 설명한 흐름을 파일과 실행 결과에서 확인해 줘”라고 요청합니다.

## 이 단계에서 익힐 기술 기반

파일과 폴더, 실행 명령, 변수·조건·반복·함수, 화면과 데이터의 차이, 오류 메시지 읽기, Git의 변경 이력부터 시작합니다. Git은 코드 파일의 수정 과정을 남기는 도구입니다. 직접 모든 명령을 외우기보다 **무슨 파일이 바뀌었고 되돌릴 기준이 있는지** 확인할 수 있어야 합니다.

실습과 함께 [MDN 시작 자료](https://developer.mozilla.org/en-US/docs/Learn_web_development), [GitHub의 Git 설명](https://docs.github.com/en/get-started/using-git/about-git)을 참고합니다. 전체 이론을 끝낸 뒤 만들기 시작할 필요는 없습니다. 자세한 순서는 [기술 기반](10-technical-foundations.md)에 있습니다.

## 자주 막히는 지점

| 증상 | 해 볼 행동 |
|---|---|
| 오류를 붙여 넣을수록 다른 곳이 망가진다 | 마지막으로 작동한 상태로 돌아가 한 오류만 재현한다 |
| 앱은 되는데 설명을 못한다 | 기능 하나만 골라 입력→처리→저장을 그림이나 글로 설명한다 |
| AI가 수십 파일을 바꿨다 | 변경 목록과 필요 이유를 확인하고 다음 작업 범위를 줄인다 |
| 계속 새 도구를 고른다 | 지금 도구로 이 과제의 완료 조건을 먼저 충족한다 |
| 도움 요청이 어렵다 | 목적·재현 순서·예상·실제·오류를 함께 보낸다 |

## 다음 레벨 E4를 준비하는 과제

작은 기능을 확인할 수 있게 됐다면, 이제 **프로젝트 하나의 흐름 전체**를 책임져 봅니다. 행사 준비 목록을 누군가 실제로 쓰게 하고, 발생한 불편 하나를 고쳐 다시 전달합니다.

다음은 이 문서가 제안하는 준비 확인 질문입니다.

- [ ] 내 환경이 아닌 곳에서도 실행 방법을 따라 할 수 있다.
- [ ] 변경한 기능의 흐름과 한계를 내 말로 설명한다.
- [ ] 실패 사례를 재현하고 수정 전후를 보여 준다.
- [ ] 모르면 무엇을 조사하거나 누구에게 물어볼지 정할 수 있다.
- [ ] 작은 목표를 작업으로 나누고 실제 사용까지 연결해 본다.
