# 13 · 바로 쓰는 진단·성과·피드백 양식

필요한 양식만 복사해 자신의 작업에 씁니다. 이름·고객 정보·로그·비밀값이 들어간 기록은 공개하지 않습니다. 공개 포트폴리오에는 허용된 자료만 남기고 필요한 부분을 가립니다.

## A · 현재 레벨과 다음 책임 점검

```text
점검 날짜:
현재 역할과 실제 책임 범위:
목표로 삼은 다음 책임:

최근 작업 1 / 2 / 3:
각 작업의 목표를 정한 사람:
각 작업의 방법을 정한 사람:

문제 정의: 확인됨 / 시도 중 / 경험 없음 / 자료 없음
구현 이해: 확인됨 / 시도 중 / 경험 없음 / 자료 없음
검증: 확인됨 / 시도 중 / 경험 없음 / 자료 없음
독립적 완수: 확인됨 / 시도 중 / 경험 없음 / 자료 없음
협업과 성장: 확인됨 / 시도 중 / 경험 없음 / 자료 없음
영향 범위: 확인됨 / 시도 중 / 경험 없음 / 자료 없음
AI 활용과 책임: 확인됨 / 시도 중 / 경험 없음 / 자료 없음

위 판단의 증거 위치:
다른 사람의 피드백:
부족한 증거 한 가지:
다음 2주에 맡을 문제와 완료 조건:
```

## B · 작은 작업을 AI와 시작하는 요청문

```text
목적과 실제 사용자:
현재 상황과 관련 파일:
원하는 동작:
입력과 예상 결과 예시:
실패·예외·권한 조건:
이번에 제외할 범위:

먼저 현재 구조와 필요한 정보를 확인해 줘.
모르는 사실은 추정과 구분해 줘.
작업을 확인 가능한 작은 단위로 나눠 실행해 줘.
각 변경의 이유와 확인 방법을 설명해 줘.
실행한 검사, 결과, 미확인 범위를 구분해 줘.
비밀값을 코드·로그·문서에 남기지 마.
외부 발송·결제·삭제 등 영향이 큰 작업은 정한 권한 범위를 지켜 줘.
```

## C · 기술 결정 한 장

```text
결정할 문제:
사용자·팀·사업에 미치는 영향:
확인한 사실과 근거:
아직 확인하지 못한 가정:

선택지 A:
선택지 B:
기존 방식 유지:

각 선택의 개발·운영·비용·위험:
이번 선택과 이유:
선택하지 않은 것과 이유:
시험·출시·복구 방법:
담당자와 검토자:
결론을 다시 볼 조건과 날짜:
```

## D · 성과를 과장하지 않는 기록

```text
작업 제목 / 기간:
출발 문제와 이전 상태:
내 책임 / 다른 사람의 책임:
AI가 수행한 일 / 내가 검토·판단한 일:

시도한 선택과 이유:
실제로 바뀐 것:
실행한 검사와 결과:
실제 사용에서 관찰한 결과:
관찰 기간·대상·표본:
측정하지 못했거나 인과가 불분명한 것:

확인 상태: 구현 / 자동 검사 / 시험 배포 / 실제 운영 / 사용자 확인
각 상태의 증거 위치:
실패·예상과 달랐던 점:
다음 작업과 유지 담당자:
```

“구현”, “검사”, “운영”, “사용자 확인”은 서로 다른 상태입니다. 해당하지 않는 칸은 억지로 채우지 말고 미확인이라고 적습니다.

## E · 다음 레벨을 위한 피드백 요청

```text
제가 다음에는 [책임 범위]를 맡아 보려고 합니다.
최근 [작업]에서 [내가 한 판단·실행]을 했고,
[결과·증거]를 확인했습니다.

1. 지금 독립적으로 맡겨도 된다고 확인된 범위는 어디까지인가요?
2. 다음 수준을 맡기려면 어떤 행동이나 결과를 더 보고 싶으신가요?
3. 이 작업에서 제가 놓친 위험·협업·사용자 관점은 무엇인가요?
4. 다음 2~6주 안에 연습할 만한 실제 과제가 있을까요?
```

## 작성 예: E4에서 E5의 책임을 연습하는 기록

다음은 **학습용 가상 사례**입니다. 실제 성과나 추천 합격선이 아닙니다.

| 항목 | 작성 예 |
|---|---|
| 이전 책임 | 예약 변경 기능을 요구사항대로 출시했다 |
| 다음 책임 | 사용자가 반복해서 막히는 문제를 찾아 우선순위를 제안한다 |
| 근거 | 같은 안내를 묻는 문의 8건을 확인했다 |
| 가설 | 변경 마감 문구가 눈에 띄지 않을 수 있다 |
| 실행 | 사용자 두 명의 실제 흐름을 보고 운영 담당자와 문구·위치를 조정했다 |
| 관찰 | 이후 2주 문의는 3건이었다. 같은 기간 사용량도 줄어 효과를 단정하지 못했다 |
| 내 기여 | 문제 분류, 대안 비교, 변경 제안, 결과 확인 |
| 공동 기여 | 운영 담당자의 업무 해석과 사용자 설명, 동료의 화면 수정 |
| 다음 확인 | 사용량을 함께 기록하고 반복 사용 시 안내 이해 여부를 확인한다 |

전후 숫자가 달라졌다는 이유만으로 원인을 확정하지 않는 예입니다. 다음 수준을 준비하는 기록에는 **판단의 질과 한계 인식**도 드러납니다.
