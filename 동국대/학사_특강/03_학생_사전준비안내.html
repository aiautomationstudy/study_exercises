  2. 브라우저가 Antigravity 앱으로 돌아가도록 허용할지 물으면 허용합니다. 앱 화면이 열리는지 확인합니다.
  3. 약관·첫 사용 안내를 읽고 진행합니다. 테마는 편한 것을 선택하세요. IDE 추가 설치는 건너뛰어도 됩니다.
  4. 앱의 계정 영역에서 로그인 계정을 확인합니다. Google One의 계정과 같아야 해당 혜택을 같은 계정으로 사용할 수 있습니다.
  5. 로그인이 끝나면 아래 자율 실행 설정과 실습 폴더를 준비하세요. 그다음 Aside 설치와 연결을 진행합니다.

로그인만 마치면 끝이 아닙니다. 첫 요청에 AI가 답하고 파일을 만들 수 있는지까지 확인해야 준비 상태를 알 수 있습니다. 개인 계정·연령 등 로그인 조건은 공식 FAQ에서 확인할 수 있습니다.

운영체제의 권한 확인 창이 나오면?

앱의 Always Proceed 설정은 macOS·Windows 자체의 권한 확인을 대신하지 않습니다. 첫 실행이나 브라우저 시험 때 파일 접근, 로컬 네트워크, 브라우저 연결 등의 확인이 나올 수 있습니다. Antigravity가 현재 실습에 필요한 접근을 요청하는지 읽고 허용하세요. 보이지 않는 권한을 미리 모두 켤 필요는 없습니다. 회사·학교 관리 기기에서 설치가 차단되면 제한을 우회하지 말고 해당 오류를 알려주세요.

도구 제작은 실습 폴더 안에서 진행합니다. 다만 아래 Aside 준비에는 CLI 설치 위치와 Antigravity 전역 지침·스킬 위치에 접근해야 합니다. 설정 요청에서 이 설치 범위를 명시하고, Windows에서 해당 접근 승인이 나오면 그 위치와 목적을 읽고 처리하세요. 서로 다른 권한 항목을 전부 같은 값으로 바꾸는 것이 아니라, 작업 진행·계획 검토·브라우저 실행에 관한 항목을 위와 같이 맞춥니다.

전역 설정과 프로젝트 설정을 함께 확인하세요

전역 설정은 여러 프로젝트의 기본값입니다. 실습 프로젝트의 설정에서 별도 값이 지정되어 있으면 전역 값을 그대로 따르지 않을 수 있습니다. Mac 프로젝트의 Permission Preset이 Inherit General이면 General의 Turbo를 따릅니다. 별도 Request Review가 지정되어 있다면 이번 실습 프로젝트를 Inherit General 또는 Turbo로 맞추세요. Plan Review와 브라우저 실행에도 별도 값이 있다면 확인합니다. 설정 범위 안내

Mac의 Turbo는 실습 폴더 밖 파일에도 접근할 수 있는 넓은 권한입니다. 폴더를 따로 만든다고 기술적으로 격리되는 것은 아닙니다. 아래 프롬프트처럼 “이 폴더에서 작업, 외부 공개·결제·다른 폴더 변경 제외”를 명확히 전달하고, 진행 중에는 작업 범위가 맞는지 확인하세요. 이런 요청은 AI의 작업 지침이며 운영체제의 접근 차단 장치는 아닙니다. 권한의 실제 범위

함께 맞춰두면 좋은 두 가지

  • 사용 모델: 대화 입력창 아래 모델 선택에서 사용 가능한 Gemini 모델을 고릅니다. 처음에는 Gemini Pro 계열을 사용할 수 있으면 선택하고, 한도에 걸리면 사용 가능한 Flash 계열로 같은 작은 작업을 이어가세요. 모델 표시와 가용성은 계정마다 다릅니다. 모델 선택 안내
  • AI Credit Overages: 추가 크레딧 자동 사용 항목이 보이면 Never로 둡니다. 이것은 작업 승인과 다른 설정입니다. 이번 사전 실습을 위해 크레딧을 구매하지 않습니다. 한도와 추가 크레딧 안내

# 동국대 AI 실습 작업 원칙

학생이 정한 목표와 완료 기준에 맞춰 작은 작업을 끝까지 진행한다.
설명은 한국어로 하고, 처음 나오는 기술 용어는 짧게 풀어 쓴다.
일반적인 디자인과 구현 방식은 스스로 결정한다.
도구 제작에서는 현재 실습 폴더에서만 파일을 만들거나 수정한다. 다른 폴더의 개인 자료를 읽거나 변경하지 않는다.
학생이 별도로 요청한 Aside 준비에 한해 CLI 설치 위치와 Antigravity 전역 지침·스킬 위치의 설치·수정을 수행할 수 있다.
실제 개인정보, 비밀번호, 결제 정보는 사용하지 않는다.
외부 공개, 메시지 발송, 유료 구매, 설치 범위 이외의 시스템 설정 변경은 이 실습의 작업 범위에 포함하지 않는다.
계획만 제시하고 멈추지 말고 구현, 실제 실행, 시험, 오류 수정, 재시험을 이어서 수행한다.
모든 웹 읽기·입력·클릭·검증은 Aside CLI와 aside-browser 스킬로 수행한다.
작업 전 aside --update와 aside guide를 읽고, 직접 조작할 때 aside guide repl을 읽는다.
첫 실습에서는 Antigravity가 aside repl로 직접 조작한다. 별도 AI 제공자 연결이나 추가 결제를 요구하지 않는다.
Aside가 안 되면 오류를 알리고 다른 브라우저 도구로 몰래 바꾸지 않는다.
작업 대상 탭에서 백그라운드로 처리한다. 마우스·전역 키 입력·창 활성화·활성 탭·데스크톱 전환으로 학생의 다른 작업을 방해하지 않는다.
브라우저에서 정상 입력, 빈 입력, 경계값, 새로고침, 좁은 화면을 실제로 시험한다.
시험 실패를 숨기거나 통과 기준을 낮추지 않는다.
test-results.md에 시험 조건, 기대 결과, 실제 결과, 통과 여부, 증거를 기록한다.
실제로 실행한 시험과 실행하지 못한 시험을 구분한다. 못 한 시험은 미검증으로 적는다.
완료 시 파일 위치, 실행 방법, 시험 결과, 남은 문제를 알린다.
요청 변경 후에는 바뀐 기능과 기존 핵심 기능을 다시 시험한다.
학생이 구조를 이해할 수 있도록 입력, 처리, 저장, 출력 흐름을 설명한다.
